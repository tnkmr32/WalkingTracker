# 外部設計レビュー観点

参照：[基本設計](./basic-design.md)

---

## 1. 要件との整合性

### 1.1 機能要件の網羅

- [ ] 要件定義書に記載された全機能が、いずれかの画面・業務フローに反映されているか
- [ ] 要件定義書にある機能で、画面設計・業務設計に未記載のものがないか
- [ ] 設計書に追加された機能・仕様変更が要件定義書と矛盾していないか

### 1.2 非機能要件への言及

- [ ] パフォーマンス要件（地図描画速度、GPS 取得間隔など）が設計に反映されているか
- [ ] プライバシー・セキュリティ要件（位置情報の扱い、ローカル保存方針）に言及があるか
- [ ] オフライン動作の方針が明示されているか

---

## 2. 画面設計

### 2.1 画面一覧・画面遷移

- [ ] 画面一覧（[screens/README.md](./screens/README.md)）に漏れがないか
- [ ] 画面遷移図（Mermaid）がすべての遷移パターンを網羅しているか
- [ ] エラー発生時・権限拒否時の遷移先が定義されているか
- [ ] 「戻る（Back）」操作の挙動がすべての画面で定義されているか
- [ ] BottomNavigationBar の状態管理（タブ間移動時のスタック）が明確か

### 2.2 各画面の項目定義

- [ ] 全画面で「画面項目一覧」が定義されているか
- [ ] 各項目の取得元（データソース）が明示されているか
- [ ] 項目の表示フォーマット（日付・時刻・数値の書式）が統一されているか
- [ ] ページネーション・スクロールの挙動が必要な画面で定義されているか（HIS001 など）

### 2.3 状態・動作の定義

- [ ] 各画面で「状態と動作」テーブルが定義されているか
- [ ] ローディング状態の表示が定義されているか
- [ ] データ0件時の表示（エンプティステート）が全画面で定義されているか
- [ ] エラー状態（通信失敗、DB エラー等）の表示が定義されているか
- [ ] 画面の業務処理で使用する DB への CRUD 操作やアセット取得について記載されているか

### 2.4 画面間パラメータ

- [ ] 全画面で受信・送信パラメータが定義されているか
- [ ] パラメータの型と値域が明示されているか
- [ ] 存在しないIDを受け取った場合（不正パラメータ）の挙動が定義されているか

### 2.5 デザインの一貫性

- [ ] デザインカンプがデザインシステム（[design-system/](./design-system/README.md)）のトークンに準拠しているか
- [ ] コンポーネントの使い方がデザインシステムの定義と一致しているか（[components.md](./design-system/components.md)）
- [ ] タイポグラフィ・カラー・スペーシングがトークン経由で統一されているか

---

## 3. 業務設計

### 3.1 業務フローの網羅性

- [ ] 正常系フローだけでなく、例外・エラー系の分岐が定義されているか
- [ ] フロー内の各処理ステップに曖昧さがないか（実装者が迷わない粒度か）
- [ ] フローの開始条件・終了条件が明示されているか

### 3.2 業務間の連携

- [ ] WLK → TRV へのデータ受け渡し（TrackPoint の提供タイミング・インターフェース）が明確か
- [ ] WLK → HIS へのデータ保存（WalkSession 確定のタイミング）が明確か
- [ ] SET（パーミッション） が未取得の状態で WLK / TRV / HIS を開こうとした場合の動作が定義されているか

### 3.3 TRV：踏破判定ロジック

- [ ] 50m のマッチング閾値の根拠が記録されているか
- [ ] 同一セグメントへの重複登録防止の条件が明確か
- [ ] GeoJSON の読み込み失敗時の挙動が定義されているか
- [ ] 踏破進捗率の計算式（距離ベース）が明示されているか

### 3.4 WLK：記録フロー

- [ ] ForegroundService の起動・停止条件が明確か
- [ ] アプリを強制終了した場合（記録が途中で切れた場合）の WalkSession の扱いが定義されているか
- [ ] GPS 取得間隔（5秒）が要件・バッテリー消費の観点で妥当か

---

## 4. データ設計

### 4.1 テーブル定義の完全性

- [ ] 全テーブルに主キー（PK）が定義されているか
- [ ] 外部キー（FK）が必要な箇所に定義されているか（例：`TrackPoint.session_id → WalkSession.id`）
- [ ] NULL 許容・NOT NULL 制約が各カラムで明示されているか
- [ ] インデックスが必要なカラムに定義されているか（例：`session_id`、`started_at`）

### 4.2 データ型・値域

- [ ] 緯度・経度のデータ型と精度が適切か（REAL / DOUBLE の選択）
- [ ] 日時カラムの型（UNIX タイムスタンプ or ISO8601 等）と精度が統一されているか
- [ ] 距離・歩数カラムの型と想定最大値が妥当か

### 4.3 GeoJSON アセット

- [ ] GeoJSON のプロパティ定義（[asset/highway-geojson.md](./asset/highway-geojson.md)）が TRV の判定ロジックと一致しているか
- [ ] セグメント数・ファイルサイズの見積もりがあるか
- [ ] GeoJSON の更新手順が定義されているか

### 4.4 AppSettings

- [ ] シングルトン制約（`id = 1` のみ）の保証手段が定義されているか
- [ ] 初期値の定義があるか

---

## 5. パーミッション設計

- [ ] アプリが必要とする全パーミッションがリストアップされているか
- [ ] 各パーミッションの用途・取得タイミングが明示されているか
- [ ] 「一度拒否」と「二度と表示しない」の挙動が区別されているか（SET001 のフロー）
- [ ] `ACTIVITY_RECOGNITION`（歩数）と `ACCESS_FINE_LOCATION`（GPS）の両方の扱いが定義されているか
- [ ] パーミッション取得後に設定が変更（ユーザーが後から剥奪）された場合の挙動が定義されているか

---

## 6. エラーハンドリング・ユーザーフィードバック

- [ ] [error-handling.md](../02-architecture-design/error-handling.md) の方針が各業務フロー・画面設計に反映されているか
- [ ] エラー時のユーザー向けメッセージ・UI（Snackbar、ダイアログ等）が定義されているか
- [ ] リトライ可能なエラーとリトライ不可のエラーが区別されているか
- [ ] GPS 信号が弱い・歩数センサーが利用不可の場合の挙動が全画面で定義されているか

---

## 7. バックグラウンド動作

- [ ] ForegroundService の仕様が [background-tracking.md](../02-architecture-design/background-tracking.md) に定義されており、画面設計（WLK001）と整合しているか
- [ ] 常駐通知の表示内容・タップ時の動作が定義されているか
- [ ] 他アプリに切り替えた場合・画面ロック時の動作が定義されているか
- [ ] Android のバッテリー最適化（Doze モード）への対処が検討されているか

---

## 8. ドキュメント品質

### 8.1 整合性・一貫性

- [ ] 画面 ID・クラス名がすべてのドキュメント間で統一されているか
- [ ] 相互参照リンク（`参照：` 行）が正しいパスを指しているか（リンク切れがないか）
- [ ] 業務フロー・画面遷移・画面仕様で同じ概念に異なる用語が使われていないか

### 8.2 記載の粒度

- [ ] ワイヤーフレームとデザインカンプの内容が一致しているか
- [ ] 「未定」「TBD」などの未記入箇所がないか（あれば課題として明示されているか）
- [ ] 実装者が判断に迷わない粒度で仕様が記載されているか
