# 実現方式：旧街道踏破判定

## 課題

ユーザーのGPS軌跡が旧街道のルート上を通過したかどうかを判定し、踏破済み区間を記録する必要がある。
旧街道のルートはポリライン（連続する座標点の列）として表現されるため、GPS点との一致を距離で判定する。

## 採用方式：ポイントマッチング（距離閾値）

取得したGPS点から旧街道の各セグメント（隣接する2点間の線分）への最短距離を算出し、閾値以内であれば踏破済みとみなす。

```
1. GPS点 P を取得
2. 旧街道の全セグメントに対して P からの最短距離を算出
3. 最短距離が閾値以内のセグメントを「踏破済み」としてEntity層に保存
4. 踏破済みセグメントの合計距離 ÷ 旧街道全体距離 = 踏破進捗率
```

## 閾値

**50m**

| 考慮事項 | 内容 |
|----------|------|
| GPS誤差 | 屋外で概ね5〜15m |
| 旧街道と現代の道路のズレ | 数m〜数十m（都市部で道路整備により経路が変化している場合がある） |
| 誤検知リスク | 閾値を広げすぎると並行する別の道も踏破済みになる |

## ルートデータ

旧街道のポリラインデータはGeoJSON形式でassetsにバンドルする。
外部APIに依存しないためオフライン動作が保証される。

## 踏破済み区間の永続化

一度踏破済みと判定したセグメントはEntity層（Room）に保存する。
アプリ起動のたびに再計算せず、差分のみ更新することで処理負荷を抑える。
